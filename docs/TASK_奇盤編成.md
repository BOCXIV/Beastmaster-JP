# パーティ編成 実施設計書

## 目的

闘獣練の挑戦前にペットパーティ編成を管理するための独立したメイン機能「パーティ編成」を提供します。プリセットのスロット数は 10、12、14、15 から選択可能で、特定の盤面やマップに縛られません。プレイヤーがゲーム標準の `XBMPetParty` 編成ウィンドウを開いた後、プラグインの専用オーバーレイから「編成を適用」を手動クリックすることで、現在のパーティを完全に置き換えます。

本機能は戦闘中の呼び笛（1/2/3号）、自動はなつ、かりる、および最後の一撃の設定とは独立しています。

## 確定済み要件

- 複数の編成プリセットに対応。
- プリセットのスロット数は 10、12、14、15 から選択可能（特定の盤面やマップに縛られない）。
- プリセットには順序付きの図鑑番号リストを保存。
- 盤面の容量未満の編成を許容（未使用スロットはリスト末尾のみに配置し、中間の空きスロットは非対応）。
- ペット選択ドロップダウンには「番号 - 魔獣名 - 獣レベル」を表示。
- 同一プリセット内での重複魔獣は禁止。
- プリセット内の魔獣が1体でも未捕獲または利用不可の場合、適用を中断し、部分的な編成は行わない。
- 適用時は現在のパーティを完全クリアし、以前のパーティの余剰メンバーを残さない。
- 編成ウィンドウを開いた際に自動で上書きせず、必ずプレイヤーが手動で「編成を適用」をクリックした時のみ実行。
- ゲームの編成ウィンドウが表示された際に専用のオーバーレイを表示。
- ゲームメモリへの直接書き込みは行わず、検証済みのネイティブ UI / Agent 操作経由で実行。

## 確定済み読み取り構造

`XBMPetParty` は右側の魔獣編成ウィンドウです。現在のクライアント構造：

```text
Value[5] = 現在のメンバー数
メンバー開始位置 = 6
メンバーブロック長 = 77
メンバー n 開始位置 = 6 + n * 77
ブロック内 +0 = 獣レベル表示
ブロック内 +1 = アイコン ID
ブロック内 +3 = 魔獣名
図鑑番号 = アイコン ID - 242000
```

最大15スロットまで解析に対応しています。

## プリセットモデル

```text
Id
Name
SlotCount
Members: List<int>
```

`Members` の長さは `0..SlotCount` です。リストの順序が加入順序となります。

適用時はゲーム内の現在の `XBMPetParty` 容量を基準とします：現在の容量がプリセットより小さい場合は先頭から現在の容量分のみを適用して通知し、大きい場合はプリセットの全メンバーを適用して空きスロット数を通知します。

## 適用フロー

1. `XBMPetParty` が可視かつ準備完了であることを確認。
2. 現在の編成容量（10、12、14、15）を取得。
3. 現在の容量に合わせてプリセットを調整し、プレイヤーに通知。
4. メンバー数、番号範囲、重複なしを検証。
5. 全メンバーが捕獲済みかつ加入可能であることを検証。
6. 原作の「パーティをクリア」操作を実行。
7. 「本当にパーティを解散しますか？」確認ダイアログのテキストを照合し、「はい」をクリック。
8. メンバー数が 0 になったことを確認後、プリセット順に1体ずつ魔獣を加入。
9. 各操作後にメンバー数とアイコンリストを検証。
10. 最終的なリストがプリセットと完全に一致したことを確認して成功を報告。
11. いずれかのステップで失敗した場合は直ちに処理を中断し、途中まで加入した状態を保持（元のパーティへの自動復元は行わない）。
